# ARM and WASM measurements, 2026-10-26

Neoverse-N1, Linux aarch64, eight homogeneous cores, verified cpuset placement.
Frequency was not verified. Rust 1.99.1, zenbench 0.1.11, Wasmtime 49.0.4,
thin LTO, no `target-cpu=native`.

Guest/library source: `574f1fb8bce2adf81b3ab632ef27589221234dba`.
The frozen native host was built at `0fde5b6ceadfdc1dccfef74f2fee5a52029c8767`;
the later change adds wasm32-only inlining and leaves the native code unchanged.
The run records the current checkout revision and the native binary hash.

All 182 groups / 940 benchmark cells completed without an unreliable or
incomplete flag. This is one exploratory process, 15–30 interleaved rounds.
It measures this CPU and Wasmtime, not browsers or other ARM microarchitectures.
The strict all-length five-process confirmation was rejected by its CPU gate
in two replicates (5.06% and 5.74% reported CPU load exceeded 5%).
Those confirmation aggregates are excluded; the gate and observations are retained.

Reproduce with Rust 1.99.1 selected on PATH:

```sh
just wasm-workloads
just bench-portable --format=json --rounds=30 --workload-id=574f1fb8-portable-full-v2
```

The builder produces four modules with explicit SIMD settings. `wide` additionally
enables Rust's experimental `wide-arithmetic` target feature and the corresponding
Wasmtime capability. It is not enabled for crate consumers. Compiler warnings
identify that experimental feature. Baseline scalar/SIMD builds retain ordinary
WASM requirements.

Before timing, all benchmark methods match native output over eight lengths,
four seeds and three chunk schedules; streaming also matches one-shot. Strict
module validation checks each declared SIMD/wide-arithmetic configuration. The
independent C corpus passes for native NEON and all four WASM configurations.

Batches, amortized setup and checksums follow the
[baseline method](arm_wasm_baseline_2026-10-26.md). The tables report measured
batch means divided by the known repetition count. Both 128-bit halves remain
live. JIT compilation and instantiation are outside timing.

The starting point for new non-adversarial byte fingerprints is XXH3. Native
rapidhash is attractive for short keys, and wide arithmetic removes its baseline
WASM multiplication penalty. Baseline WASM can favor XXH3 instead. Existing
persisted FNV identifiers retain their original formula; changing algorithms
requires an explicit ID/schema migration. These are non-cryptographic hashes.

The tuning was guided by perf, including JIT symbols. The paired WASM change
preserves widening 32-bit products instead of general 64-bit vector multiplication.
The corresponding NEON unzip pairing reduced the fixed profiler workload from
5,200,085,928 to 4,662,676,434 instructions. WASM-only entry-point inlining reduced
the targeted 4-byte XXH3-64 case from 9.779 to 5.516 ns/hash in separate probes.
These probes are exploratory; the full table above is the final matrix.

Remaining gaps are visible against the comparison ports, especially some
mid-size and seeded/custom-secret cases in the raw matrix. Performance parity
remains a per-workload measurement goal.

```text
run-heavy: done rc=0 292s | peak-RSS 0.04GiB | min-avail 14974MiB | peak-load 1.39
```
