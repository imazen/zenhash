# zenhash vs twox-hash vs xxhash-rust, 2026-10-07

Decision this supports: zenhash's XXH3 is at least as fast as the two most
used Rust xxHash crates from 64 bytes up on this CPU, and with the
`avx512` feature 24-30% faster than twox-hash from 64 KiB up. Below 64
bytes the three are within about 10% of each other, and which one leads
changes from run to run.

## Environment

- CPU: Intel Xeon, family 6 model 207 (Emerald Rapids), reported as
  "Intel(R) Xeon(R) Processor @ 2.10GHz", 4 vCPUs in a Firecracker VM
  (shared host; neighbours not controlled). AVX-512 available.
- OS: Linux 6.18 (VM kernel), rustc 1.97.0 (2d8144b78 2026-07-07).
- Profile: cargo `bench` (release, no LTO), built **without**
  `-C target-cpu=native`; zenhash and twox-hash pick SIMD at runtime,
  xxhash-rust uses what the compile target enables (SSE2 on x86-64).
- Single thread. Inputs are generated in memory before timing (xorshift
  bytes); no IO in the timed region. Every library hashes the same buffer.
- zenbench 0.1.10, `--no-busy-gate` (the resource gate stalled the run on
  this VM). Benches in a group are interleaved round by round; the CI column
  is zenbench's paired 95% interval of each competitor's mean time relative
  to zenhash (positive = competitor slower).

## Reproduce

```sh
git clone https://github.com/imazen/zenhash && cd zenhash
git checkout 2da9a2982621a3a1dab7f080086b29147a4379aa
cargo bench --bench hash -- --no-busy-gate
cargo bench --bench hash --features avx512 -- --no-busy-gate
# one group: ZENHASH_BENCH=xxh3_64/240 cargo bench --bench hash -- --no-busy-gate
```

Competitors, pinned in `Cargo.toml` dev-dependencies: twox-hash 2.1.5
(features std, xxhash32, xxhash64, xxhash3_64, xxhash3_128) and
xxhash-rust 0.8.19 (features xxh3, xxh32, xxh64).

## Results

Run-to-run drift on this VM is large: the same competitor's absolute time
moved up to 20% between runs, and groups that run identical code in both
builds (all inputs of at most 240 bytes) differ between the two tables
below by up to 20 percentage points against a competitor. Compare within a
table, and read sub-10% differences at small sizes as noise.

## Where zenhash loses

- XXH32 and XXH64 at 16 bytes: 2-15% slower than one or both competitors in
  both runs. The generated code matches xxhash-rust's nearly instruction for
  instruction (zenhash saves one more register), so the gap is call-level
  overhead or code placement.
- XXH3 at 8-64 bytes: within about 10% of xxhash-rust in either direction,
  depending on the run.
- Default build, 64 KiB and up: within 0-3.5% of twox-hash, on either side.
  Both use AVX2 there.
